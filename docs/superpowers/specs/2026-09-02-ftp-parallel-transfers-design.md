# FTP 并行传输与客户端布局优化设计

日期：2026-09-02  
目标分支：`main`（免费公开版）  
实现分支：`codex/ftp-parallel-transfers`

## 1. 背景与目标

FTP 客户端当前支持多选，但所选文件和目录仍通过同一个 `FtpClient` 逐项串行传输。传输期间 `FtpClientViewModel.Busy` 会禁用文件浏览和其他传输命令，且连接级 `CancellationTokenSource` 只能通过断开连接间接取消。大量小文件还会为每条 FTP 命令分别向 UI Dispatcher 投递日志更新；服务端每次更新都重新拼接最多 500 行日志，形成高频 UI 工作，表现为服务端 OwO! Win Deployer 界面卡死。

本设计实现以下可追溯需求：

- **FR-FTP-01 多文件并行**：上传和下载均可同时处理多个文件，默认 4 个，可调 1-8 个。
- **FR-FTP-02 大文件并行下载**：不小于 64 MiB 的文件优先使用最多 4 个 FTP 会话分段下载。
- **FR-FTP-03 后台队列**：传输不占用目录浏览连接；传输期间仍可浏览并继续加入任务。
- **FR-FTP-04 可取消**：支持取消单个文件、取消目录扫描和取消全部任务。
- **FR-FTP-05 传输预览**：页面内队列显示方向、文件、目标、进度、速度、剩余时间、状态和错误。
- **FR-FTP-06 紧凑连接状态**：连接后隐藏完整连接表单，只显示服务器身份、连接摘要和断开按钮。
- **NFR-FTP-01 响应性**：千文件扫描和传输期间，客户端与服务端 UI 均保持可交互。
- **NFR-FTP-02 完整性**：失败或取消的下载不得覆盖现有完整文件；成功后才原子替换目标。
- **NFR-FTP-03 失败隔离**：一个文件失败不取消其他独立任务。
- **NFR-FTP-04 兼容性**：服务器不支持分段下载时自动回退单通道，不影响普通 FTP/FTPS 服务器。

## 2. 范围与非目标

### 范围

- FTP/显式 FTPS/隐式 FTPS 客户端的上传、下载、目录扫描和队列管理。
- 本项目 FTP 服务端在高并发和高频日志下的响应性。
- 客户端连接后布局、传输队列和协议日志布局。
- 中英德三语资源及自动化测试。

### 非目标

- 不实现跨应用重启的持久化队列或断点续传。
- 不实现单文件分段上传。标准 FTP 没有通用可靠的区间结束语义，多个写会话可能损坏远端文件。
- 不替换现有零依赖 FTP/FTPS 协议实现，也不引入第三方 FTP 库。
- 不修改 FTP 用户、权限、TLS 证书固定和服务端配置格式。

## 3. 根因与约束

1. `FtpClientViewModel` 把浏览和传输绑定到同一个 `_client`、`_cts` 和 `Busy` 状态。
2. `DownloadAsync`、`UploadAsync` 及目录递归方法均使用顺序 `foreach`。
3. 一个 FTP 控制会话不能安全并发交错 `EPSV/PASV`、`REST`、`RETR`、`STOR` 和完成响应，因此不能对现有 `_client` 直接使用 `Task.WhenAll`。
4. 客户端 `AppendLog` 每行都投递 Dispatcher；服务端 `FtpServerViewModel.OnLogged` 每行都投递 Dispatcher 并执行 `string.Join`。千文件传输会产生数千次控制命令和 UI 更新。
5. 服务端已按控制连接异步运行 `FtpSession`，并有总连接、用户和 IP 连接上限；新调度器必须使用有界连接预算。
6. 传输状态服务不得依赖 WPF。跨线程事件由 ViewModel 汇入 UI Dispatcher，保持服务与展示分离。

## 4. 方案选择

采用独立 `FtpTransferCoordinator`，为目录浏览与后台传输使用不同的 FTP 控制会话。相比把并发逻辑继续写入 639 行的 `FtpClientViewModel`，该方案让队列状态机、并发限制、取消和协议回退可以独立测试。相比引入第三方 FTP 库，该方案保留现有证书固定、日志和协议兼容行为，并把变更限制在 FTP 功能域。

## 5. 组件设计

### 5.1 连接快照

`FtpConnectionSnapshot` 是不可变值，包含主机、端口、TLS 模式、用户名、运行期密码、远端基准目录和显示名称。连接成功时创建快照；密码只保存在进程内存，不持久化到队列或日志。

显示名称规则：连接来自已保存凭据时优先使用凭据昵称，否则使用 `用户名@主机:端口`。后续切换表单或凭据不会改变当前连接摘要。

### 5.2 传输协调器

`FtpTransferCoordinator` 位于 `Services/Ftp`，不引用 WPF 类型，职责为：

- 接收下载或上传根项目并返回批次标识。
- 管理批次与文件任务的生命周期。
- 将目录扫描结果流式写入有界工作队列。
- 维护逻辑文件并发限制和总 FTP 会话预算。
- 发布不可变状态快照或变更事件。
- 取消单项、取消批次、取消全部并在关闭时等待后台任务退出。

每个物理文件对应一个 `FtpTransferJob`。目录根项目对应一个可取消的批次；扫描到的子文件关联该批次。队列状态为：

`Scanning -> Queued -> Connecting -> Transferring -> Completing -> Completed`

取消分支先进入 `Canceling`，资源退出后进入 `Canceled`；错误分支进入 `Failed`。状态只能单向前进，终止状态不可重新进入运行状态。

### 5.3 目录规划器

`FtpTransferPlanner` 负责把根文件/目录展开为物理文件任务：

- 本地目录通过异步后台枚举逐项产出，不在 UI 线程递归计算总大小。
- 远端目录使用独立规划会话递归 `MLSD/LIST`，不改变浏览会话的当前目录。
- 扫描结果边产生边入队，传输无需等待完整目录枚举。
- 扫描任务持有批次取消令牌；取消后停止继续枚举，已运行的同批次任务也被取消。
- 目录创建作为文件任务的前置动作幂等执行；取消时只删除本次新建且仍为空的本地目录，不删除既有内容。

### 5.4 会话工厂与传输执行器

`IFtpTransferSessionFactory` 隔离网络边界。生产实现从连接快照创建、认证并定位到基准目录的全新 `FtpClient`；测试替身只模拟该外部边界。

普通文件占用一个逻辑文件槽和一个 FTP 会话槽。上传和下载任务不会共享 `FtpClient`，取消时直接取消令牌并释放该任务拥有的控制与数据连接，避免污染浏览会话的协议状态。

## 6. 并发与带宽策略

- 默认逻辑文件并发数为 4，可在 1-8 间调整。
- 所有扫描、普通传输和大文件分段共享最多 8 条活动 FTP 会话。
- 调低并发数只限制后续启动，不强制中断已运行文件；调高后立即唤醒等待任务。
- 连接预算使用有界异步闸门，等待过程可取消，任何异常路径都在 `finally` 释放。
- 收到临时 `421`、`425` 或传输开始前的瞬时套接字错误时最多重试 2 次，退避 500 ms、1500 ms。
- 认证失败、权限拒绝、证书变化和路径错误不重试。
- 已写入部分上传内容后不自动重试，以免无续传协商时重复或覆盖数据。

并发设置只在当前进程内生效，本次不增加配置文件字段。默认值对本项目服务端的 20 条总连接上限留有余量；若远端限制更低，临时错误退避后仍失败的任务会显示明确原因，其他任务继续。

## 7. 大文件分段下载

当远端文件大小不小于 64 MiB 时，执行器尝试最多 4 段并行下载：

1. 通过 `SIZE` 或可信的 `MLSD size` 获取总长度。
2. 在目标目录创建唯一的 `.owo-part-<id>` 临时文件并预分配总长度。
3. 每段使用独立 FTP 会话，通过 `REST <offset>` 后执行 `RETR`。
4. 各段只读取其负责的确定字节数，并使用偏移写入 API 写入临时文件的对应区间。
5. 所有分段完成后校验临时文件长度，刷新并关闭句柄，再原子替换目标文件。

非末段到达区间末尾后关闭其专用数据与控制连接，不复用已中断的协议会话。任一服务器拒绝 `SIZE`、`REST` 或未按请求偏移返回数据时，取消其余分段、删除临时文件，并对该文件重新执行一次单通道下载。回退只发生一次，避免循环重试。

分段数取 `min(4, max(2, ceil(size / 64 MiB)))`，因此达到阈值的文件至少使用 2 段，更大的文件最多 4 段。每段仍受全局 8 会话预算限制。

## 8. 取消、清理与断开

- 单文件取消只取消该任务，不影响其他批次或文件。
- 取消目录批次会停止扫描并取消该批次下排队和运行中的文件。
- “全部取消”取消所有扫描、排队和运行任务。
- 下载只写唯一临时文件；取消或失败时删除临时文件，原目标保持不变。
- 上传取消后在账户权限允许时尝试删除远端残留。清理失败时任务显示残留远端路径，不宣称已完全取消。
- 用户点击“断开”且存在非终止任务时，使用应用本地化对话框确认。确认后先取消并等待队列退出，再关闭浏览连接。
- 应用关闭时走同一异步关闭流程；后台任务内部捕获并记录异常，不把异常抛到 UI 线程。

## 9. UI 设计

### 9.1 连接状态

未连接时保留当前凭据、主机、端口、用户、密码和 TLS 表单。连接成功后整个表单替换为约 44 px 高的紧凑状态栏：

```text
● 已连接 · <凭据昵称或 user@host:port>
  <user@host:port> · <TLS 模式>                                  [断开]
```

状态点使用现有成功色，连接摘要允许截断并提供完整工具提示。断开按钮继续使用现有危险操作样式。

### 9.2 文件区与传输队列

双栏文件区占用连接表单释放的高度。传输队列是页面底部独立、可折叠的全宽区域，不是模态窗口，也不嵌套在文件卡片内。只有存在任务或历史记录时自动展开；用户可随时折叠，传输不暂停。

队列工具栏显示活动/排队计数、聚合速度、1-8 并发选择、清除已完成、全部取消和折叠按钮。行高固定，列表启用行与列虚拟化，列包括：方向、文件名、目标、大小、进度、速度、剩余时间、状态和取消图标按钮。熟悉图标使用现有 Segoe MDL2 Assets，并为不熟悉操作提供工具提示。

现有固定 110 px 协议日志改为默认收起的“连接日志”展开区。传输队列和日志同时收起时，文件区获得全部剩余高度。

### 9.3 UI 更新节流

客户端与服务端协议日志先写入线程安全缓冲区，由 Dispatcher 定时器每 100 ms 最多合并刷新一次；日志保留现有行数上限。进度、速度和 ETA 每 250 ms 发布一次 UI 快照，不为每个网络块投递 Dispatcher 工作。

服务端连接列表沿用 1 秒刷新节奏。连接增删事件只标记“需要刷新”，由定时器合并处理，避免并行分段会话频繁重建整个集合。这一节直接处理服务端程序传输期间界面卡死的根因。

## 10. 错误处理与可观测性

- 每个任务保存用户可读错误类别与消息；一个任务失败后调度器继续处理其他任务。
- 审计日志正文保持中文，记录批次开始、完成、取消、失败计数和总字节，不记录密码。
- 协议日志继续遮蔽 `PASS`，连接快照的 `ToString` 不包含密码。
- UI 明确区分“已取消”“失败”“失败且远端可能残留”“已回退单通道”。
- 队列完成后提供成功、取消、失败汇总；失败行保留供检查，清除已完成不会清除仍需处理的失败。

## 12. 测试设计

新增 `OwOWinDeployer.App.Tests`（`net10.0-windows`）并镜像 FTP 服务目录。遵循红-绿-重构：每个生产行为先以能抓住对应破坏的失败测试固定契约。

### 单元测试

- 文件调度器不超过可调逻辑文件并发数。
- 全局 FTP 会话数永不超过 8，异常和取消后许可正确释放。
- 取消一个文件不取消其他文件；取消批次只影响同批次任务。
- 目录规划器流式产出且在取消后停止枚举。
- 状态机拒绝从终止状态回到运行状态。
- 临时错误仅按规定次数退避，确定性错误不重试。
- 下载成功后才替换目标；失败和取消删除临时文件并保留原目标。
- 日志和进度合并器把高频输入限制为受控 UI 更新次数。

### 回环集成测试

使用本项目真实 `FtpServer`、临时目录和测试账户：

- 多个上传和下载文件确实重叠运行并保持内容一致。
- 取消一个运行文件后，其他任务完成且新会话仍能列目录。
- 128 MiB 测试文件启用至少两个分段，合并内容与源文件一致。
- 模拟拒绝 `REST` 后自动回退单通道并得到正确文件。
- 千文件目录扫描可取消；服务端停止时所有会话在限定时间内退出。

测试不以墙钟速度提升作为断言，避免环境波动；通过活动会话重叠、最大并发观测值和字节一致性证明并行行为。

### UI 与质量门禁

- 构建整个解决方案并运行全部测试。
- 运行 `scripts/check-i18n.ps1`。
- 实际启动 WPF 应用检查连接前后布局、缩放、长德语文本、队列折叠、单项取消和断开确认。
- 检查客户端和服务端在千文件任务期间仍可操作，且日志不会逐命令触发完整文本重建。

## 13. 验收标准

1. 选择多个文件后，至少两个文件可同时处于 `Transferring`，默认最多 4 个逻辑文件。
2. 大于等于 64 MiB 且支持 `REST` 的下载显示 2-4 个分段；不支持时自动回退并完成。
3. 单项取消在用户操作后立即进入 `Canceling/Canceled`，连接关闭不等待整个文件传完。
4. 取消或失败下载不破坏原目标，也不留下 `.owo-part-*` 文件。
5. 千文件目录扫描与传输时，客户端和服务端窗口仍能滚动、切换页面和响应按钮。
6. 连接后不显示主机、端口、用户名、密码和 TLS 编辑控件，只显示紧凑连接摘要与断开按钮。
7. 队列折叠不暂停任务；可在传输期间继续浏览并加入新任务。
8. 中英德资源键完全对齐，解决方案构建和全部自动化测试通过。

## 14. 设计影响

实现时同步更新 `docs/DESIGN.md` 的 FTP 功能设计，记录浏览会话与传输会话分离、并发预算和关闭生命周期。该变更不修改持久化 schema、版本号或发布变更日志；版本与 CHANGELOG 仅在实际发布时按仓库发布流程更新。
